    1. What this is

    Milst Screener is a monitor for the HIP-3 perpetual markets on Hyperliquid — the xyz dex, where synthetic perps track US and foreign equities, indices, FX, commodities and baskets — plus a second, walled-off universe of the main-dex crypto perps (BTC, ETH and the top names by open interest).

    The design has one central idea: the heavy work happens once, on the server. A small Node process polls Hyperliquid, fetches and archives candles, samples open interest, computes every feature (momentum, volatility, reference prices, funding history, session studies, signals, sector aggregates) and caches the result. Browsers read a single pre-computed snapshot. Nobody's browser talks to Hyperliquid, so the per-IP rate limit is never a per-user problem and a cold start takes seconds rather than minutes.

    How data reaches your screen

    • Snapshot — the market table is rebuilt every ~15 seconds and served whole from /api/snapshot. The status line's updated field is the server's last successful poll, not your last fetch.
    • Push stream — while the live stream (Server-Sent Events) is healthy the status line reads push live and the browser pulls the moment the server's data changes. The stream carries versions, never payloads: it tells the browser what changed, the browser fetches it.
    • Fallback poll — if the stream drops, the browser polls at the cadence in the refresh selector (15s to 15m, default 30s). This setting is idle while the stream is up.
    • WebSocket universe feed — server-side, the universe subscribes to Hyperliquid's real-time asset contexts for price / funding / OI at zero rate-limit cost; REST drops to a slow reconciliation poll while the socket is healthy.
    • Persistence — open interest, funding history, the candle archive, the signal ledger, notes, messages and accounts live on a mounted volume and survive restarts and redeploys. A redeploy serves a warm table within a poll or two.

    Two universes, one wall

    The Stocks | Crypto switch in the nav is a hard wall: separate universes, separate benchmark (the S&P 500 perp for stocks, BTC for crypto), separate histories, never mixed in one list. Session concepts (gaps, overnight holds, cash sessions) do not exist on a 24/7 crypto tape and vanish in that scope. Crypto history is retained for 31 days by design, so long moving averages and year-to-date columns show honest dashes there. The one deliberate exception: BTC may join a stock set in comp and ratio comparisons, aligned on the hours both legs traded.

    Honesty rules that run through every tab

    • A dash is a dash. Missing history, an unqualified baseline, a retired data series — all render as an explicit blank, never a guess, an interpolation or a zero.
    • One code path. A level, a score or a record is computed once on the server and restated by every surface. The board, the drawer, the alerts and the Telegram wire cannot disagree because none of them recomputes.
    • Frozen claims. Every signal is ledgered at the mark it fired at, with its void and target frozen, and scored out of sample. The record is the part to trust; the card is the part to read.
    • Stamped prose. A note or a message that names a ticker carries the price it was written at, so every later read carries the move since.

    2. Getting in — accounts, invites, sessions

    The terminal has per-person accounts. An operator mints a single-use invite link from Admin › Access; opening it validates the code, moves it into a short-lived HttpOnly cookie and redirects to a bare /join, so the code leaves the address bar before anything renders and never lands in browser history or a Referer header. You pick a handle and a password; the invite is burned inside one database transaction, so two people opening the same link cannot both get in — the second sees "already used".

    Sign in

    /login — handle and password. Sessions are signed tokens carrying your account id and a per-user epoch; they last SESSION_DAYS (30 by default). A ⎋ button in the nav signs this browser out (/logout).

    Forgot your password

    /reset — enter your handle and a six-digit code is sent to your linked Telegram (the quiet window and the hourly cap are bypassed). The code lasts 10 minutes, works once, dies after five wrong guesses, and at most three are sent per hour per account. Every outcome — unknown handle, no Telegram, throttled — returns the same answer, so the page is not a directory of who has an account. No Telegram linked? Ask the operator for a reset link instead.

    Sign out everywhere / disable

    Resetting a password or an operator disabling an account bumps that account's epoch, which invalidates every session it holds without touching anybody else. Under the old shared password, removing one person meant rotating the password for everyone; that failure is what accounts replaced.

    Legacy shared password

    A deployment that still has SITE_PASSWORD set accepts it as a shared door; a shared-password session that arrives after accounts exist lands on /claim to pick a handle. Your alerts, rules and notes carry over automatically — they were already keyed to your browser's signed handle. Once everyone has claimed, the operator sets LEGACY_SHARED_PASSWORD=0 and the shared door is closed for good.

    Roles

    • Member — sees the public feature set (whatever the operator has opened to the group) plus every personal surface: watchlist, layouts, alerts, notes you can read, messages, positions.
    • Operator (admin) — everything, plus the Admin tab: accounts and invites, feature visibility, nav menus, alert recipients, the message read-through and its audit log, lane maintenance. The first account is bootstrapped with ADMIN_PASSWORD, which stays as a break-glass login for when an operator locks themselves out. A member can be promoted with make operator in Admin › Access.

    Scripts and curl

    The JSON API accepts HTTP Basic with the shared password (curl -u friend:PASSWORD …/api/snapshot) so a script needs no cookie jar. /api/health stays open without any credential — it is the platform healthcheck. Eight wrong passwords from one IP lock that IP out for 15 minutes; Basic attempts count against the same lock.

    Privacy notice. On this deployment the operator can read every message, including conversations they are not in. Every such read is written to an audit log shown in the Admin panel, and the Messages tab says so plainly. Write accordingly.

    Group lens — sectors and industries

    The group toggle re-renders the same board with one row per sector (GICS plus asset classes) or industry (the finer curated split — Semis vs Software vs Memory, Banks vs Capital Markets). Each cell is the weighted average of exactly the rows the names view shows, computed only over members that have the value (a missing window is excluded and the weights renormalize, never zero-filled); hover discloses coverage. Best · Worst (pinned to 24h) is the aggregate-liar detector — whether the group number is everyone or one name dragging the rest — read against Cohesion (90-day average internal correlation: high = the label trades as one block, low = a stock-picker's bucket). Click a group row to drill in: the table flips back to its members with a chip to clear. Industry rows marked = sector have no curated split yet.

    Action strip — heating · cooling · strongest bid

    The collapsible strip under the table is the rate-of-change read next to the table's levels, and it always describes exactly the rows the table shows (scope, window, filters, drill and group lens all apply).

    • accel = the window's natural fast leg (1h→15m, 4h→1h, 1d→4h, 7d→1d, 30d→7d) minus the window's own pace, both relative to the tape. heat = accel + 0.6·tanh(ΔOI/8) + 0.4·clamp(RVOL−1): flow can confirm an acceleration, never replace it; RVOL is dropped at 7d/30d, not faked.
    • HEATING = positive accel with flow agreeing — what is starting. COOLING = names still ahead of the tape whose pace has died — with a high MOM this is the take-profit read. "Never went anywhere" makes no list at all.
    • STRONGEST BID ranks the server's dip-reclaim claims off the 5-minute archive (equities, last 4h): the deepest peak→trough dip, the fraction reclaimed, minutes since the low, ranked dip × reclaimed ÷ √minutes. Demand response, not momentum.
    • M on every chip is the momentum level: high/high = ride, high/stalling = exit, low/accelerating = new rotation. In a group lens the strip regroups (share-of-tape replaces RVOL as the volume confirm; the bid column stays name-level because dips don't aggregate).

    The 1d movers row above the table lists the day's biggest moves as chips; click one to open the name.

    Crypto scope

    Adds the tape strip (crowd pays, breadth, total OI and its weighted delta, BTC's day, alt-season gauge), the Casc and 24h Liqs columns, and BTC as the benchmark. Session columns (Gap, Sess) vanish. Crypto claims and features run on compressed horizons throughout the app.

    7. The tabs

    Each tab is one question asked of the same rows. Tabs marked operator-only by default ship closed to the group until the operator opens them in Admin › Feature visibility; a closed tab is absent from the ribbon and its routes refuse, not hidden. Where a tab has a per-universe split, the scope pills decide which universe you are reading.

    Focus — today's six most tradeable equities

    Six seats, stamped once at the 09:30 ET cash open, one late fill at +1h, then immutable for the day — a compressed morning scan, not a signal. It never reshuffles at 10:47 because a number ticked; yesterday's list stays viewable exactly as stamped.

    • How seats are earned — a disclosed loudness ordering: |gap σ| + RVOL excess + |ΔOI| + a flat earnings boost + a small headline count, every unit in the name's own distribution. Max 2 seats per industry cluster, so six seats are six trades rather than one theme wearing six tickers. The cut line discloses what just missed and why. Foreign-home names are excluded (their gap anchors to the wrong exchange for an ET stamp).
    • Liquidity floors — two walls the operator sets in Admin (a 24h notional minimum and an OI minimum), applied before loudness is compared: a seat you cannot exit at your size is not a seat. Names that fail a wall get their own BELOW FLOOR roster with the wall they failed and how far it would have to fall. The floors in force at 09:30 are frozen onto the record.
    • The +1h columns — sVWAP, 1H HI, 1H LO fill once at 10:30 ET from the 5-minute archive and freeze; the 1H RANGE bar shows where the open sat in the hour's eventual range vs the 10:30 print — "who won the first hour".
    • The chart (▦) — 5m/15m/1h/4h candles over 72h from the local 5m archive, off-session time shaded, the frozen levels drawn verbatim, the session VWAP labelled.

    Funds — the 13F watchlist

    Tracked institutional filers with filing badges, per-fund books (holdings, quarter-over-quarter delta, concentration) and the once-per-quarter season summary. 13F snapshots are quarter-end positions filed up to 45 days late: positioning history, never the current book. Long US-listed equity and listed options only. Curating the watchlist (whale add|rm|mute) is an operator verb; reading it is the tab. The terminal's fund, etf and holds verbs read the same lane.

    Trend — the EMA 13/21 ladder

    An EMA 13/21 ribbon evaluated on D1 · H12 · H4 · H1 for every market in the active scope, ranked into long and short leaderboards (top 10 per side, ≥2/4 alignment). Per rung: green = price > EMA13 > EMA21 (stacked), yellow = the middle state, red = stacked the other way. The score counts aligned rungs — 4/4 is an established trend on every rung; 2–3/4 means higher timeframes lead and you wait for the lower ones to agree.

    • RETEST fires when the last few bars probed into the 13/21 zone on a trending rung while the close held the EMA21 side — the continuation pullback (long) or rally-into-resistance (short). The badge carries a clock-matched volume multiple when the baseline qualifies: ~1× or less is a quiet, healthy pullback; ≥2× means the level is being fought. A retest is promoted verbatim into the signal ledger as tretest / tretestdn, with entry = mark, void = the rung's EMA21 and target = that rung's prior swing.
    • Width — average EMA13–EMA21 spread across aligned rungs, in percent: two 4/4s are not the same trade when one holds a 0.08% ribbon and the other a 2% ribbon. Age counts consecutive D1 days stacked this side (N+ = extends past available history). Δ21 is the live distance from the H1 EMA21 — the proximity-to-entry number.
    • Ranking — by score, then fresh-first: a day-3 trend is the entry, a day-40 trend is the chase. Ticker badges carry the funding-percentile flag (crypto) or the earnings badge (stocks).
    • Chart button — a candlestick chart of any rung with the ribbon, the retest zone banded at the ladder's own levels and a crosshair OHLC + EMA readout. Every annotation is the board's own payload restated. Bars inside the EMA seed window render dimmed with no ribbon.

    H1 is the hourly spine; H4/H12 are UTC-aligned aggregations of it; D1 is the daily series with the live mark driving the forming bar. EMAs need 26+ bars per rung; a market missing a rung is excluded and counted in the header.

Vertical = activity heat from volume and volatility. Top-right = accumulation, top-left = distribution, bottom half = quiet. Bubble size = 24h volume. Click a bubble for its members.

    Correlation — matrix, pairs, COMP/G, ratios, baskets

    • Matrix — pairwise correlation of daily log returns over the chosen lookback (30d–1y for stocks; 4h/1d/7d intraday grids for crypto), cluster-ordered (UPGMA on correlation distance) so blocks along the diagonal are real co-movement families. The number of overlapping days is in every hover — a ±0.9 on 12 days is noise. Focus search isolates tickers; top by vol widens or tightens the universe (20/40/60).
    • Pair view (click a cell) — hedge β (units of B per unit of A), the beta-adjusted spread ln(A) − β·ln(B) with its mean ±1σ band and z-score (beyond ±1.5–2, A is rich or cheap vs B), and the rolling correlation that says whether the relationship is stable enough to trust.
    • Co-movers & hedges (click a ticker label) — proxies and contagion map on one side, natural hedges on the other. Strongest pairs below surfaces the tightest relationships across the set.
    • COMP/G — N names rebased to 100 at a chosen anchor (presets, date picker, or drag the amber line), or spread mode (each name minus the equal-weight basket of visible names, in percentage points). Runs on closes already loaded, so it never adds a fetch.
    • Ratio — synthetic pair candles A/B at 1h · 4h · 12h · 1d with an honest EMA200 (drawn only where 200 bars exist). BTC may face a stock, aligned on the hours both traded.
    • Baskets operator-only by default — custom equal-weight baskets (basket create MAG7 AAPL MSFT …) usable as virtual tickers in COMP/G, ratios and the Δ vs ⬒ column. A visual layer only: never a benchmark under signal math.

    Funding — the heatmap

    A row per market, a column per time bucket, readable at 1h, 8h or 24h, in one of two units:

    • Annualized (default) — a cell is the bucket's mean hourly rate × 24 × 365, the convention every other funding readout uses. The timeframe is a resolution: one market reads one number on every grid, and all three share one colour cap (the 8h grid's 98th percentile) so a zoom never repaints a cell.
    • Per bucket — a cell is what a 1× long paid over that bucket (the hourly spine summed), so the timeframe changes the quantity: the same market reads ~8× larger per 8h than per 1h, and each timeframe has its own colour cap. Remembered per browser; every tooltip carries both.

    Red = longs pay (crowded long, carry is a cost), green = longs receive. A bucket whose spine covers under half its hours is hatched rather than drawn as zero — a gap in the data and a market that went flat mean opposite things to anyone sizing a position. The newest column is always the last complete bucket. Beside each row's window mean sits its current funding (this hour's rate off the live snapshot), so carry building or fading reads as now vs mean; rows rank by open interest and can be sorted by carry side, |carry| or the now column; the client trims to top 25 / 50 / all.

    Sessions — when the returns happen

    • Session decomposition (the flagship) — what an overnight (close→open), weekend (Fri→Mon) and cash (open→close) hold actually pays, pooled one equal-weight bet per calendar boundary across the equity class, compounded into equity curves. The shaded band is the running funding drag: an edge that dies net of funding is a donation. A rising overnight curve against a flat cash curve is the classic overnight effect.
    • The clocks — hour-of-day activity in each market's own volume norm; the funding clock; a day-of-week 7×24 heatmap and return seasonality by hour. Read with sample-size humility.
    • Structure panels — cross-ticker clustering by the shape of the trading day; asset-class overlays (equities vs FX vs commodities). Panels unlock as the 180-day hourly spine accrues; an empty panel means insufficient coverage.

    Signals — unusual conditions, ranked and audited

    A signal is an unusual condition, ranked — never a prediction. Score = unusualness now (0–50) + historical edge (0–50): the market's own base rate when it has ≥8 occurrences, else the asset-class pooled rate at a 30% discount, else a token score. Every base rate shows n, median forward outcome and hit — evidence, not adjectives. unproven = a flag without history; neg exp = past occurrences lost money on average (ranked as noise). Per-universe visibility: the operator opens the crypto and equity slices separately.

    How to read a card

    Every condition renders in the same four-line grammar. Line 1: the event chip, the plain-language reading, and — at the right edge — when the condition appeared and the ledger claim it is scored against (at the frozen mark, with time to resolution). Line 2: the evidence in one fixed format — scope (own base rate / class-pooled / thin) · n · median · hit · expectancy · horizon — plus any qualifier pills (unproven, neg exp, no live edge, earnings proximity). Line 3: the mechanical play — side, target, void, R/R — frozen from the claim when one is open. Line 4: the single corroborating thing to watch.

    Self-audit — the part to trust

    Every fired signal is ledgered at its mark and resolved at its horizon, out of sample. The record blends back into scoring (weight grows with resolved count, so trust migrates from backtest to reality), and event types whose live record shows no edge get capped automatically. The accuracy panel shows: live hit/median vs claimed (the honesty gap); pf, the profit factor that catches the 55%-hit event that still loses money; calibration buckets that audit the scorer itself (if 55+ scores don't hit more than <35 scores, the ranking is broken); a ⛔ stop-aware re-score of every claim as if the void had been a hard stop; and the bracket track, where outcomes cap at whichever frozen level — target or void — was touched first.

    Playbooks, prime, decay, confluence

    • Each signal states a side, a mechanical level that voids it and a target from the historical median; the R:R is scored and poor structure is penalized.
    • ★ prime = ≥60% hit, positive expectancy, sound structure at fire time (+6 score).
    • Signals decay past their claimed horizon (amber, ×0.6) and drop at 2× — a stale signal is not a signal.
    • Confluence: multiple same-side conditions on one name compound; the bonus is earned — once 15+ resolutions exist on each side it scales to the measured lift of with-company firings and drops to zero if agreement doesn't prove out. ⇄ means long and short fired on one name: flagged, no bonus for anyone.
    • Earnings / macro guard: session-spanning signals on a name reporting ≤1 ET day out (or with a macro print ≤1 day out) have their evidence capped at 8 points and cannot be prime — a stated prior, labelled on the card. Once ≥5 tagged claims resolve per event, the tab shows the conditioned record beside the ordinary one.

    Ticker history and self-tuning

    The search bar loads any name's full claim-by-claim audit trail — what fired, at what score and mark, what it claimed, what happened, open claims counting down — and the signal-type selector browses one event across all tickers. Each gated event also runs 2–3 candidate thresholds as shadow variants that ledger silently on identical bookkeeping; a challenger is promoted only on ≥30 out-of-sample resolutions per side with a real expectancy beat. Whole-strategy shadows (gap fade, breakdown reclaim, failed-breakout fade, MA50 pullback, post-earnings drift, liquidity sweep) earn a record on the same terms before anything visible ships. The full roster is in Signals reference.

    Actionable — names at a swing trigger

    Every name currently sitting at a swing trigger — one row per name per side, with the entry, invalidation and target you would actually use. The morning list: the other tabs tell you what is true, this one tells you what is actionable.

    • Nothing on this board is computed here. Every claim froze its side, void and target at fire time; those frozen values are what you see — the same numbers the track record was scored against. Entry is the one live number, because that is what entering now costs.
    • R:R is net of funding. A three-week hold on a crowded long at 45% APR donates ~2.6% of notional before the trade does anything; the headline R:R is net of expected funding across the horizon and can flip sign (a short in a name paying to be short is paid to wait). Hover for the gross figure.
    • EV is expectancy in R for entering here: the event's out-of-sample hit rate applied to this row's own net geometry. Below 8 resolved fires EV stays blank and the row sits in no record yet, ranked by net R:R.
    • Age and falling off — bars in trigger measured in the setup's own timeframe. A row leaves at 10 bars, when the reward:risk from the live mark drops under 1.2 (2.0 to enter as CONFIRMED), or when price passes its void.
    • Flags — ⚠ earnings inside the horizon (flagged, never filtered; the no earnings in horizon checkbox hides them), blue ◆ macro event inside the horizon, +n other detectors on the same name and side (corroboration, not extra trades). Filters: side, the 2:1+ setups class (level-triggered, stop at a real chart level) vs positive-EV grinders (the statistical family against a 1σ void).
    • Horizons of 3 days or longer only for equities (2 days for crypto). Both universes, scoped by the pills, never mixed. A new CONFIRMED row is what the setup alert class announces.

    Backtest — cross-sectional long/short, and the Score duel

    A client-side backtest on the daily returns already in your browser, so parameter tweaks are instant and cost the server nothing. Ranking rules are deliberately non-fitted; the honest overfitting risk is you, picking parameters by eye.

    • Signal roster — seventeen rules in six families: trend (momentum, sector-relative, residual, high proximity), reversion, risk (low vol, low idio vol, low beta, anti-lottery), perp-native (funding carry), flow (volume trend, OI change — sign-ambiguous, the direction toggle decides), and the live-score variants (Blend M0, the daily mirror of the Markets momentum, plus V1–V4 each adding one candidate upgrade). The live-score family is the promotion bench for the board's Momentum column.
    • Controls — lookback, hold window, book quantile, rank gate, weighting, structure (long/short, long-or-flat, short-or-flat), costs, funding, and the in-sample | out-of-sample split.
    • Target picker — pick one name and the tab switches to single-asset mode: the same signal runs as a timing rule (sign, ±0.5σ or ±1σ entry bands), buy-and-hold becomes the dashed benchmark, a position ribbon shows when the rule was long/short/flat, and the round-trip count is shown first because a Sharpe on ten round trips is an anecdote. Several names = a custom universe, ranked among themselves.
    • Reading the curve — net, gross, benchmark and equal-weight universe. Judge on out-of-sample net vs equal-weight: beating the benchmark with a long/short book is table stakes.
    • Score duel — once per UTC day the server snapshots Momentum and MOM+ for every name and, when the next day's prices land, computes each column's rank IC (Spearman correlation of the ordering with the realized next-day return). Forward, out of sample, persisted across redeploys. The verdict gate refuses to call a winner before 60 days or |t| ≥ 2; the live-disagreements list shows which names the two columns argue about and why.

    Housing — macro housing and MBS board

    The backdrop behind the homebuilders, mortgage servicers, REITs and banks in the universe. Seven FRED series pulled in full history, refreshed every 6 hours, warm-cached: the Freddie Mac 30-year conforming mortgage rate, single-family vs multifamily starts (SAAR), months' supply of new homes (6+ historically reads as a buyer's market), new-home sales and the median price, and ICE BofA BBB corporate OAS standing in for non-QM spreads.     Liquidity — Fed net liquidity

    Net liquidity = total assets − Treasury General Account − ON RRP, on the weekly H.4.1 dates (Thursdays ~4:30pm ET; the board refires after each release and every 6h otherwise). Shown in dollars and as % of nominal GDP, with year-to-date change by component signed by liquidity effect (holdings add when they grow; TGA and ON RRP add when they shrink — a blue TGA bar means Treasury ran its balance down), balance-sheet composition (Treasuries, agency debt, MBS), the TGA / ON RRP drains, and two plumbing-stress reads the usual pages leave out: bank reserves (what the Fed targets as "ample"; the 2019 repo spike came near $1.4T) and SOFR − IORB (persistently positive = collateral scarce, reserves tight). Ten FRED series, everything normalised to billions before any arithmetic. QT end is derived: the first week after the 13-week change in holdings stopped being negative.

    Congress — STOCK Act disclosures

    Periodic Transaction Reports filed with the House Clerk, parsed into individual trades that name a ticker in the universe.     Insiders — SEC Form 4

    Section 16 transactions — officers, directors and 10% holders reporting their own trades within two business days — for the equity roster, rotated through EDGAR two names a minute.     11. Signals reference — the engine

    How a condition becomes a card, a claim, a record and an alert. The full per-event reference with every threshold, stamp and knob is a separate page: Signal, study & shadow reference.

    Pipeline in one pass

    data (hourly spine · daily · funding · OI · Coinalyze · Finnhub earnings · EDGAR)
  ↓ studies      in-sample base rates, per market per event, memoized to the data version
  ↓ signals      live surveillance: condition fires → intensity 0–50 + evidence 0–50
  ↓ ledger       claim frozen at fire: mark · side · void · target · 30d σ · context stamp
  ↓ gates        episode re-arm · universe whitelist · geometry (no inverted or degenerate levels)
  ↓ resolve      at horizon: realized (play-signed) + stop-aware track + bracket track
  ↓ records      blend back into evidence · no-edge cap · earned confluence · variant promotion
  ↓ surfaces     Signals cards · Actionable board · drawer record · ticker history · AI report
  ↓ stream       one sequenced event log → browser toast / bell · Telegram · push

    Scoring

    • Evidence is expectancy-centred: an event whose average outcome is ≤0 scores 0 evidence and wears neg exp, however loud the condition. Otherwise min(1, avg/scale)·30 + max(0, hit−0.5)·2·20, with scale = 0.5R for R-united events and 0.8% for %-united ones.
    • Source: the market's own study if n ≥ 8; else the asset-class pool if n ≥ 12 at a 0.7 discount (unproven); else a token 6–8 points. Crypto pools in its own bucket.
    • Live blend: once an event has ≥5 live resolutions, stats blend study and live record with weight resolved/(resolved+25). No-live-edge cap: ≥10 resolved, hit <50%, median ≤0 → evidence capped at 8.
    • Universe lanes: 40 signals per universe, so a volatile crypto day cannot evict the equity board.

    Ledger mechanics

    • Frozen geometry — at fire: entry mark, play side, void level, target (absolute), 30-day daily σ for R normalization, score and prime flag. Never re-derived, never moved.
    • Episode re-arm — if a claim resolves while its condition still fires, no new claim opens until the condition lapses for a full build. One episode, one claim.
    • Units — premium in bp; the R-united set (big move, breakout, breakdown, funding flip, vol shift, OI flush, funding–price divergence, the shadows, cascade, funding extreme) in R via σ; everything else in %. Crypto levels are built in log space so σ constructions cannot produce negative prices.
    • Context stamp — funding and its percentile, 5d OI change, position in the 30d range, the benchmark's 24h move, session or hour-of-day bucket, day of week — so records can be sliced later. Absent means unknown, never null-padded.
    • Persistence — ledger.json plus an append-only archive on trim; optional weekly off-site backup to a GitHub repo.

    15. Running and deploying

    Locally

    npm install
DATA_DIR=./data npm start
# open http://localhost:3000

    Node 22.5+ (the built-in WebSocket client and SQLite). On first boot the server backfills candle history for every market — the slow part, once, server-side; the table fills progressively and the status line shows syncing X/Y.

    Railway

    1. Push the repository to GitHub; New Project → Deploy from GitHub repo. Nixpacks detects Node and runs node server.js from railway.json.
    2. Add a volume mounted at /data and set DATA_DIR=/data. Without it every redeploy loses the OI history.
    3. Set ADMIN_PASSWORD, then the optional keys above. Do not set PORT.
    4. Settings → Networking → Generate Domain; set PUBLIC_URL to it so push and Telegram links resolve.
    5. Open the domain: the first account is created at /bootstrap with ADMIN_PASSWORD. Mint invites from Admin › Access.

    Keep the service always-on: the whole benefit is the warm cache. Redeploys keep the OI history and candle archive; only stale spines are re-fetched. The build stamp in the status line is how you tell a fresh deploy from a stale one; every asset URL carries it, so a browser can never run last build's client against this build's API.

    16. Security model

    • Sessions are stateless HMAC tokens in SameSite=Lax, HttpOnly cookies carrying the account id and a per-user epoch. Bumping the epoch (password reset, disable, sign out everywhere) invalidates one person's sessions only.
    • Two gates, in order. The site gate answers 401 to anyone without a session (the login page for pages, JSON for the API). The feature gate, registered last, answers 403 to a route whose owning feature is closed to the caller. Routes no feature claims pass through. The escalation path (health, login, logout, the AI unlock pair, /api/features) can never be closed by a flag write.
    • Two locks on every privileged write. The manifest gate decides audience visibility; the handler's own admin check decides authorization; both must pass. Opening a tab to the group can never hand the group its write verbs.
    • Cross-site writes are refused before any handler runs when the browser says the request came from another site (Sec-Fetch-Site: cross-site).
    • Headers on every response: nosniff, X-Frame-Options: DENY, same-origin referrer, HSTS over HTTPS, and a per-request-nonce Content-Security-Policy (report-only until the operator flips CSP_ENFORCE=1; violations are counted on /api/health).
    • Login throttling: eight wrong passwords from one IP lock it for 15 minutes, keyed on the trusted proxy's forwarded address. Reset codes are capped and the reset page never reveals whether a handle exists.
    • Invites burn inside one database transaction; codes never reach a Referer header or the history. Attachments are typed by magic-byte sniff and non-image files are served as downloads with a sandboxed CSP. Text a member typed is escaped everywhere it renders, including inside inline scripts (the JSON is HTML-safe).
    • Wallets are public addresses; the app reads clearinghouse state and holds no key.
    • Operator read-through is a separate, admin-gated, audited surface (see Admin), and members are told.
    • Rate budgets: a weight-based limiter keeps Hyperliquid calls under the per-IP budget; FRED, Finnhub and EDGAR lanes are paced to their published limits; AI spend is metered per user and per group.

    17. Glossary

    HIP-3 · xyz
    Hyperliquid's permissionless perp-deployment standard; xyz is the dex whose synthetic equity, index, FX and commodity perps this monitor covers. The "main dex" is Hyperliquid's native crypto book.
    Perp · mark · oracle
    A perpetual future has no expiry; funding payments keep it near the reference price. The mark is the perp's own price; the oracle is the reference (the cash market, frozen near the last print while that market is closed). Prem is the gap between them.
    Funding · APR · carry
    The hourly payment between longs and shorts. Shown annualized (×24×365). Positive = longs pay. Carry is window-average funding per unit of realized vol.
    OI · ΔOI · regime tag
    Open interest — standing positioning. Its change with price tells one of four stories: longs+, squeeze, shorts+, unwind.
    Window
    The selected lookback (1h–30d) every windowed column shares.
    RVOL
    Relative volume, clock-hour matched against the prior month.
    vs tape · DownCap · Hit%
    Relative strength against the universe median; the share of red-tape moves a name ate; the share of red-tape bars it beat the median.
    Momentum · MOM+
    The board's −100…+100 score, and its candidate under adjudication.
    Squeeze · OI/Vol
    Short-squeeze susceptibility; standing positioning relative to daily flow.
    Gap · overnight · cash session · home session
    The close→open move; the hold from close to open (and Friday to Monday); the open→close hold; the exchange whose clock a foreign-listed name's session follows.
    Signal · claim · ledger · record
    An unusual condition; the frozen entry/void/target it was scored against; the store of every claim; the out-of-sample outcome statistics.
    Void · target · R · R:R · EV
    The level that invalidates a claim; where it aims; one unit of risk (entry-to-void distance, or 1σ where levels are σ-built); reward-to-risk; expectancy in R.
    Prime · confluence · decay · re-arm
    A high-quality signal at fire; same-side agreement across conditions; the fade past horizon; the one-episode-one-claim gate.
    Shadow · variant · promotion
    A candidate threshold or strategy ledgering silently; the process by which one replaces the incumbent on out-of-sample evidence.
    Setup · CONFIRMED
    An open claim on the Actionable board; one that clears the record and geometry gates and is announced as an alert.
    BMO · AMC · DMH · TBD
    Earnings sessions: before the open, after the close, during hours, date known but session not.
    13F · N-PORT · Form 4 · PTR · 8-K
    Quarterly institutional holdings; monthly fund holdings; insider transactions; congressional Periodic Transaction Reports; a material-event filing.
    TGA · ON RRP · H.4.1 · SOFR · IORB
    The Treasury's account at the Fed; the overnight reverse repo facility; the Fed's weekly balance-sheet release; the overnight funding rate; interest on reserve balances.
    EMA 13/21 · rung · retest
    The trend ribbon; one of its four timeframes; a pullback into the ribbon that held.
    Scope · universe · lane
    Stocks or crypto; the set of markets in a scope; one server-side data or scan loop.
    Feature key · act · scope key
    A tab's visibility switch; a write verb's switch; a per-universe slice of a tab.
    Snapshot · spine · archive
    The cached table; the hourly candle series every feature is built on; the SQLite candle store.

    18. Troubleshooting

    The dot is amber and "updated" is minutes old.
    The server's poller stalled or Hyperliquid is rate-limiting it; the browser is fine. It recovers on its own; an operator sees the ops alert and the health endpoint.
    A column shows dashes.
    Read the hover. Usually: history still backfilling after a deploy (hourly features fill within ~10 minutes), crypto's 31-day retention (long MAs, YTD), a baseline that does not qualify (RVOL on 7d/30d, DownCap under 20 matched bars), or a feed key the deployment lacks.
    A tab I used to see is gone.
    The operator changed its visibility, or you flipped to a scope where it has no meaning. Gated tabs are absent, not hidden.
    I see the wrong build / a stale UI.
    Compare the build in the status line with the latest delivery. Every asset URL carries the build stamp, so a hard reload always fetches the current client.
    The refresh selector does nothing.
    Correct while the status reads push live: updates arrive as the server has them, and the selector only paces the fallback poll.
    No Telegram alerts arrive.
    Check the bell's Delivery section: linked, the class enabled, not inside quiet hours, not at the hourly cap (held messages are disclosed). The panel log shows Telegram's own error text. /status to the bot reports what it thinks.
    The regenerate button on a report is disabled.
    The report is fresh for everyone; the freshness line counts down to the cooldown, or names the material change that unlocked it. The server enforces the same rule with a 429.
    The AI answered with 🔒 / "budget".
    Generation is locked or the group pool for today is spent; an operator can admin unlock or admin reset-reports. Your own daily cap is separate.
    My phone shows different columns than my desktop.
    By design: the first phone visit starts from the mobile preset and the active layout is per browser. Saved layouts and the watchlist sync.
    A note or message "moved" after I edited it.
    It did not: the timestamp and the price stamp are written once; only the words changed, and the edit is disclosed.
    I lost access after a password reset.
    Intended — a reset signs out every other device. Sign in again with the new password.

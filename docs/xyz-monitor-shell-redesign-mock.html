One shell, one scale, three controls

The site grew a tab at a time and every tab brought its own chrome. Today the stylesheet carries 25 font sizes, 18 radii, 158 paddings and 60-odd button, pill, segment and chip classes, and the client hard-codes another 147 sizes inline. Nothing enforces a scale, so nothing looks like it belongs to anything else. The fix is not a restyle: it is five sizes, four gaps, three radii, three controls, one shell, and deleting everything that is not one of those.

4 · The tokens  the whole system fits on one card each; anything not here is deleted

Type · five sizes, two families

--fs-xs 11meta · legend · 24 listed aftermono only
--fs-sm 12controls · table cells · +36.4%mono, controls
--fs-md 13body · subtitles · navdisplay
--fs-lg 15Section titlesdisplay 600
--fs-xl 20Hero numbersdisplay 700

Numbers and machine facts are mono. Words are display. A size is never chosen per element; it is chosen per role, and there are five roles. The 7, 7.5, 8, 8.5, 9, 9.5, 10, 10.5, 11.5, 12.5, 13.5, 14, 16, 17, 18, 19, 22, 23, 26 and 30px in the stylesheet today all map onto these or die.

Space · four gaps, three radii, one height

--sp-1 4inside a control
--sp-2 8between controls
--sp-3 12between groups · panel padding
--sp-4 20between sections
--r-1 4--r-2 7--r-3 10inner · control · panel
--ctl-h 28one height

158 distinct paddings become four gaps. 18 radii become three, by role: inner element, control, panel. Every control is 28px tall so a row of them is a row, not a skyline.

Controls · three shapes, one base

.segone ofgrouped options, one selected
.btn↓ CSV columns ↻an action · quiet · icon
.chipNVDA ✕ watchlist ✕a removable fact

Everything interactive in a controls row is one of these three, on one .ctl base (height, radius, border, font). Presets are a segment, not pills. A date is an input inside the segment it belongs to. The 60 classes in the stylesheet today become aliases of these, then get deleted one tab at a time.

5 · What this pins down

Tokens are the only sizes

After the pass, font-size, padding, gap and border-radius in styles.css may only take a var(--…) from the five, four and three above. A test greps for any literal pixel value on those properties and fails the suite on the first one, so the scale cannot drift back a tab at a time — which is exactly how it drifted out.

Inline sizes leave the client

The 147 font-size:…px strings in public/js become classes (t-xs…t-xl) or SVG text styles that read the same tokens. A renderer that needs a size it cannot name from the scale does not get a new size; it gets a conversation about which role it is.

One shell, two rows

The header, the status line and the tab strip collapse into one 44px row (mark · nav · scope · session) and one mono meta line (counts · bench · live · build · freshness). The regime and macro strips leave the shell and become the first line of the tabs they describe. Everything a tab needs above its content is its own controls row, and nothing else.

Controls rows read left to right, always

What (universe, window, anchor, search) · cut (grouping, top N, sort, labels) · actions (CSV, refresh, columns). A hairline separates the first two zones; actions sit at the far right. A tab that cannot fit this grammar has too many controls, and that is the finding, not a reason for a fourth zone.

Aliases first, deletions second

Step one ships the tokens and the three controls and makes every existing class an alias, so no tab breaks and the suite's CSS pins keep passing. Step two walks the tabs — Markets, Drawdown, Sectors, Funding, Sessions, then the rest — replacing markup and deleting the alias behind it. Each tab lands with a before/after screenshot in the PR.

Mobile gets the same system, not a second one

The 28px control height is already a thumb target; the row wraps by zone rather than by control, so actions drop to their own line before what and cut split. The shell row wraps once: mark and session on line one, nav on line two. No separate mobile stylesheet.

6 · What it deliberately does not do

No rebrand

Same colours, same two typefaces, same dark surface. The palette was never the problem; the number of ways it is applied was.

No new components

Nothing here needs a library, a framework or a build step. It is fewer classes in one stylesheet, not more of anything.

No content changes

Every number, label, tooltip and column stays. Where a control becomes a segment, the words on it are the words it had.

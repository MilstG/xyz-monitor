xyz-monitor // signal · study · shadow reference

Every event the engine can fire, how it triggers, how it's measured, what renders, and what reaches a phone. Written against the codebase as of 2026.07.27. File anchors: detection math in src/compute.js, assembly & fire sites in src/poller.js, rendering in public/app.js, routes in server.js, pins in test/test.js.

Every entry below is described on the same four axes, because those are the four things you'd tune independently:

MeasurementHorizon, sign convention, unit, how the claim resolves, what the study measured.EV_META / EV_META_MAIN, resolver in poller.js

Pipeline in one pass

data (hourly spine · daily · funding · OI · Coinalyze deriv · Finnhub earnings · EDGAR) ↓ studies (in-sample base rates, per market per event, memoized to data version) ↓ buildSignals — live surveillance: condition fires → mkSignal(intensity 0–50 + evidence 0–50) ↓ openLedger — claim frozen at fire: mark0 · psd · stp · mv · tgt · sd0 · context stamp ↓ episode gate (rearm) · universe gate (evAllowed) · geometry gate (stop/claimGeometryOk) ↓ resolveLedger — at horizon: realized (play-signed, event unit) + realizedS (stop-aware) ↓ record sets → Bayesian blend back into evidence · no-edge cap · confluence lift · variant promotion ↓ surfaces: Signals cards · Actionable board · drawer record · ticker history · AI report ↓ trigger stream (one canonical sequenced log) → transports: browser toast/bell · Telegram push
One-code-path contract. Every level on every surface (entry, void, target, R/R, lateness) ships on the server payload, frozen by the ledger at fire time. The client sorts and formats; it never recomputes a level. The moment two surfaces derive the same number separately they can disagree — that rule is pinned all over the test suite.

Scoring model

Score = intensity (0–50, per-event formula: how unusual the condition is right now) + evidence (0–50, expectancy-centered). Displayed on every card; drives ranking and the calibration audit.

Evidence (evPts / evidence in poller.js)

Ledger mechanics

MechanismHow it works
Frozen geometryAt fire: mark0 (entry mark), psd (play side), stp (void level), mv (target distance %, rounded), tgt (absolute target price — stamped because mv cannot be turned back into a price), sd0 (30d daily σ for R normalization), score0, pr. Never re-derived, never moved — a bias flip later leaves the frozen claim to resolve untouched.
Episode re-armIf a claim resolves while its condition still fires, the key parks in rearm and cannot re-open until the condition lapses for ≥1 full build. One episode = one claim; kills serial pseudo-replication on persistent conditions (weekend premium, all-day big move). Applies to shadows too.
ResolutionresolveLedger revisits each claim at resolveAt: realized = at-horizon outcome, signed by the play side, in the event's unit. realizedS = stop-aware parallel track (outcome capped as if the void had been a hard stop; stopped flags a touched void). Session-calendar events (gap, gapfade) resolve at the next cash close instead of a wall-clock horizon.
Unitsprem → bp; R-united set (bigmove breakout breakdown fundflip volshift oiflush fpdiv reclaim mapull failbrk pead sweep airead casc fundext) → R via sd0; everything else %.
Geometry gatesstopGeometryOk / claimGeometryOk refuse inverted or degenerate levels at fire. Crypto levels are built in log space (logGeo) so σ constructions can't produce negative prices; equity keeps the exact additive arithmetic so its record stays byte-comparable.
Context stampEvery claim (shadows included) carries fire-time features for slicing: fnd/fndP (funding + 31d percentile), oi5, rngP (position in 30d range), mktR (benchmark 24h move — BTC for crypto, SPX proxy for xyz), ses (xyz: rth/on/wknd) or hod (crypto: asia/eu/us/late), dow. Absent means honestly unknown, never null-padded.
Chain dedupResolved re-fires ≤2d apart chain into one displayed episode on charts — recorded, but not re-marked.
Persistence/data/ledger.json + append-only ledger-archive.jsonl on trim; optional off-site GitHub backup behind LEDGER_BACKUP_REPO + LEDGER_BACKUP_TOKEN (blob-sha skip, bytes verbatim). Crypto claims from before CRYPTO_EPOCH (2026-07-26 UTC) stay purged — old additive geometry produced fabricated targets.

Trigger stream — the canonical event log

The poller owns one sequenced, persisted event stream (emitTrig → trigSeq, trigSeen, ring). Every transport (browser toast, bell panel, Telegram) is a thin consumer with its own eligibility filter — eligibility never gates the stream itself, so a channel's thresholds can't censor the record of what fired.

PropertyMechanism
Cursor semanticsGET /api/triggers?since=seq → events = everything above your cursor (what to interrupt for); recent = cursor-independent display list (the bell panel is a window onto the server ring, not a second copy). no-store.
Announce onceKeys are per-claim AND per-fire (coin|side|ev|t0) with the frozen t0 — rebuilds never re-announce, and a restart with the persisted announced-set + ledger re-fires nothing. This property is what lets a push channel survive a deploy.

Telegram delivery (push transport)

Second consumer of the same stream. Everything deciding what a message says lives as pure functions in compute.js (pushEligible/pushFmt, delegating to trigEligible — Telegram and the browser can never announce different things); poller.js holds only the wire. Fully dormant without TG_BOT_TOKEN: no timers, no writes, no noise — unset the var and the transport doesn't exist.

MechanismDetail
LinkingPanel mints a single-use code (PUSH_LINK_TTL 10 min) carrying the minting browser's owner handle → human sends /start CODE to the bot → chat bound to that browser in one unforgeable step. /stop always works (control of the Telegram account outranks any cookie); /status//help report state. Inbound via getUpdates poll every 20s — no webhook, no public URL needed.
OutboxBounded (PUSH_QUEUE_MAX 50 — overflow drops oldest, counts, and the next delivered message discloses it), drained every 1s, paced 1 msg / 3s (PUSH_SEND_GAP). First eligible item, not first item — a digest scheduled for the end of a quiet window can't head-of-line-block an urgent alert. 15s abort on every request (one hung connection would otherwise stall the whole sequential lane).
Per-recipient capPUSH_CAP_HOUR 20/h — held, not dropped; disclosure protects you from believing silence means nothing fired. force bypasses for command replies (a /stop confirmation is not an alert).
Failure handling429 → backoff for their retry_after; 403 (blocked/deactivated) handled; up to PUSH_MAX_TRIES 5; last 40 outcomes in the panel log (PUSH_LOG_RING); Telegram's error description surfaced verbatim — the difference between "alerts don't work" and "the token is wrong".
Per-recipient prefsClass selection (empty = default set), per-name/side/threshold trig filters, mute, quiet hours (from/to + tz — scheduling, not subscription), daily digest hour (digestTick every 5m). Chat ids masked in the panel (…1234). Bell panel shows YOUR recipients only; admin manages everyone in the Admin tab.

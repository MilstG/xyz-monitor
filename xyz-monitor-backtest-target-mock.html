Pick a name, not just a universe

The Backtest tab tests a cross-sectional rule: rank a universe, long one tail, short the other. There's no way to ask the smaller question — "does this signal work on NVDA?" This mock adds a typeahead target picker (no dropdown — the roster is too long) and shows what the tab becomes when the target is a single name: the cross-section collapses, so the controls that only exist to slice a cross-section have to go with it.

◆ mock · synthetic prices, nothing is wired to live data

Type in the target box (try NV, OPEN, BTC) · ↑↓⏎ to pick · flip the scope to search the crypto roster · every panel below reacts to how many names are picked.

ControlOne nameWhat it means once the cross-section is gone
signalkeepsSame score, same code path — it just stops being a rank and becomes a level. Sector-relative momentum still demeans against its sector peers (they're loaded even when they aren't the target); the funding/OI/volume rules still need their column shipped for that name.
lookbackkeepsUnchanged. Still ignored by the M0–V4 blends, which run fixed 1/7/30d horizons.
rebalancekeepsHow often the position is re-decided. On one name this is the trade-frequency knob — 1d flips a lot and pays for it in fees.
taker bps · in-sample · holdkeepsUntouched. The IS/OOS split matters more here, not less — see the honesty note in the caption.
directionkeepsStill decides which sign you're buying: long strong = long when the score is positive, long weak = the inverse.
structurere-readsSame three options, time-series meaning: long/short flips with the sign, long-only is long or flat, short-only is short or flat.
universeoffSuperseded by the picked name. Dimmed with the name shown in its place, so it's obvious the picker won — never silently ignored.
book (10/20/33/all)offA quantile of one name is that name. The knob's actual job — only trade the conviction extremes — moves to entry.
gate (signal must agree)offThere's no rank left to disagree with; the sign of the score is the position. Folded into entry.
entry (new)appearsHow far from zero the score must be before taking a position: > 0, ±0.5σ, ±1σ of that name's own trailing score distribution. Higher threshold = fewer, higher-conviction trades and more time flat. This is the single-name replacement for the quantile.
weighting → sizingre-readsSame three buttons, one position: equal → flat 1×, by signal → size scales with |score|, inverse-vol → vol-targeted size. Label flips to sizing.
vs ⬒ basketkeepsStill a comparison line, still enters no stat. Buy & hold of the picked name joins it as a second yardstick.
latest-rebalance bookreplacedA long/short book of one row is a waste of a panel. It becomes current position + trade log, plus a position ribbon under the curve.
equal-weight linereplacedThe universe EW line means nothing here. Buy & hold of the name takes its place — that's the only benchmark a single-name rule has to beat.
Score duel panelkeepsUniverse-level rank IC, computed server-side and independent of these controls. Unchanged, sits below as always.
◆ Two calls I'd like you to make — before I wire any of this into app.js
1 · What should 2+ picked names do?
The mock treats them as a custom universe — rank just those names, long/short their tails, everything cross-sectional stays on. It's the honest reading of "test these five", but the tails get thin fast: five names at a 20% book is one long and one short, and btRun currently refuses to run under 8 names at all. The alternative is capping the picker at one name and keeping this strictly a single-asset feature. My preference is the custom universe with a visible thin book warning and the 8-name floor relaxed to 4 — it costs one guard rail, and "MAG7 only" is a question people actually have.
2 · Should a single-name run be allowed to look good?
One name over ~120 days at a 5d rebalance is roughly 24 decisions, and crypto ships ~90 days, so it's more like 18. A Sharpe on that is an anecdote with a decimal point. The mock states the trade count next to every stat box and puts the warning in the caption rather than blocking the run. The stricter option is to refuse to print Sharpe under some trade count and show "n too small" instead — the same spine as the Score duel's verdict gate. Say the word and it ships gated.
◆ How it lands in the code — roughly 200 lines, no server change, no new payload
  1. State: one field — state.backtest.picks: [] (coins, not tickers), plus entry: 0. Both persist through savePrefs and the hash like every other backtest param.
  2. Picker: reuses the COMP/G typeahead wholesale — .cg-pick / .cg-sugg / .cg-sg markup, the same universe-validated resolve (free text never matches), the same chip anatomy with ⬒ reserved for baskets. Scoped to the active scope, so crypto search never returns equities.
  3. btUniverse(): when picks.length, filter to those coins and skip the sector/equity branches — every other consumer (btMatrix, btRun) is untouched because they already take whatever rows that function returns.
  4. btRun(): one new branch for picks.length===1 — position from the score's sign against the entry threshold instead of a quantile sort, sizing from the same weighting value, trade log accumulated on every position change. Fees still charge on turnover, funding still accrues on the held side; the cost model doesn't change at all.
  5. Render: mode is derived, never stored — picks.length decides which controls get .na, which panel renders, and which caption prints. Nothing about universe mode changes shape.
  6. Tests: the suite already exercises btRun; add cases for a one-name run (position flips at the threshold, trade count matches the ribbon, fees ≥ the zero-cost run) and for the picks-override-universe precedence.
